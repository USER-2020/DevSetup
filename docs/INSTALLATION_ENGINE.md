# Installation engine

The planner maps selected tool IDs to audited WinGet or Homebrew package IDs. It produces a reviewable plan and labels operations that can need elevation. The executor runs one plan item at a time with `shell: false`, captures bounded output, and persists in-memory job state for the current session.

A Dry Run is always labeled as a simulation and never reported as an installation. The explicit follow-up action creates a LIVE plan. Before it starts, the executor resolves and verifies the provider with `brew --version` or `winget --version`. For Homebrew it allowlists `/opt/homebrew/bin/brew`, `/usr/local/bin/brew`, and finally `brew` on `PATH`, so a Finder-launched macOS application does not depend on the user's shell configuration. It emits narrowly scoped provider and job progress updates: provider checking/available/unavailable, then `preparing`, `installing`, `verifying`, and a final job status. The renderer uses the Homebrew provider events for its real-time toast; it cannot submit a command through this channel.

After a live command succeeds, the executor verifies the catalogued ID with `brew list --versions <package-id>` for a Homebrew formula, `brew list --cask <package-id>` for a Homebrew cask, or `winget list --id <package-id> --exact` on Windows. A job is reported as installed and verified only when the appropriate provider query succeeds; otherwise it requires manual review. A future persistence adapter must recover interrupted work as `interrupted`, never replay destructive work automatically.

PHP versions 8.1 through 8.5 are the currently supported version-management flows. An alternate-version plan has two catalogued actions: install `php@<version>`, then link that formula with `brew link --overwrite --force php@<version>`; PHP 8.5 uses the current `php` formula. The activation action has a stronger verification rule: the linked Homebrew `php` binary must report the selected version.
